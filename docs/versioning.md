# 版本号与发布规则

采用 `v主版本.次版本.修订号`，从严判断。依据码伴 CodeCompanion 的发布标准建立，但版本与迭代独立计算。

| 类别 | 规则 |
| --- | --- |
| 大更新 | 必要的不兼容升级或核心使用方式实质扩展，必须说明迁移和分级理由 |
| 小更新 | 兼容功能、余额服务、局部界面与交互改进 |
| Bug 修复 | 恢复原有预期行为，不扩大功能范围 |
| 文档与维护 | 文档、图库、测试、内部重构、构建检查不单独升版本、不增加迭代 |

提高某一位只清零右侧，数字可以超过 9，不机械进位。混合新增功能和修复通常仍是小更新。一次发布可含多个提交，只计一次迭代。

首个已公开源码的构建版本为 0.10.0，映射到固定提交 3ee166bc7f7ee02dc882a9342f1340348d25fe0d，作为第 1 次公开产品迭代；早期本地 0.9.x 不追溯虚构为 GitHub Release。本次 DeepSeek 和 UI 变化为 v0.11.0，第 2 次迭代。

发布前维护 VERSION、README、CHANGELOG 和下载索引；标签及 Release 仅在上传验收后创建。文档补充并入所属版本，不修改已有标签或原始下载包。App CFBundleVersion 是独立构建序号，不因文档变更或项目版本变化自动增加。
